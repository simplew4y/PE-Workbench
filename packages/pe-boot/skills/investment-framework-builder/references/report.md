# 📝 投资框架：七节文档交付

投资框架正文固定为以下七节，草稿、聊天预览、确认后的版本及下载使用同一份结构化数据。不能用“框架总览＋命题条目＋缺口”替代，不能仅在聊天写七个标题却只保存旧条目。新提案必须使用工具 schema 的 `schemaVersion: 2`、`title`、`sections`；字段名称及约束以当前工具定义为准。

| 章节 | sections 字段 | 必须回答及呈现 |
| --- | --- | --- |
| 1. 研究设定 | researchSetup | 研究对象与问题、投资期限、分析师偏好、信息截止日。简短字段；未知写未确定，信息截止不是生成日期。 |
| 2. 当前判断 | currentAssessment | 为什么值得研究或投资、主要回报来源、最大不确定性、相比上一版的实质变化。一段短文与状态项；最后生成。 |
| 3. 公司如何创造价值 | businessModel | 如何赚钱、客户为何购买、竞争优势，以及经营驱动如何传导到利润和现金流。简短说明、业务驱动关系及 KPI。 |
| 4. 投资判断与其他解释 | investmentJudgments | 每项判断的依据、依赖假设、正反证据、替代解释、置信度、验证和失效条件。稳定判断 ID 关联来源及后续监控。 |
| 5. 市场预期、估值与回报 | valuation | 市场预测与研究预测的可比差异、悲观/基准/乐观情景的假设及价值、估值区间、回报来源和催化剂时间。缺行情时明确无法判断当前回报空间。 |
| 6. 什么情况下我们错了 | monitoring | 指标关联哪些判断、当前观察、预警及失效阈值、阈值依据、检查频率、来源与触发后的动作。 |
| 7. 证据、未知问题与版本变化 | evidenceAndChanges | 可追溯引用及质量/限制、未解决问题及影响、新证据怎样改变旧判断。首次不制造变化；没有变化如实说明。 |

## 📝 事实不足时保留结构

未知数值保留为 null 或 schema 允许的未知说明，不用 0 填空。缺外部取证、市场价格、共识、模型理由或用户偏好时，在对应节解释限制，并在末节记录所需证据及影响；不因此省略章节，也不为通过 schema 编造数据。一份券商模型不是市场共识，模型输入价格不是实时行情，后来的实际不能假装为原时点已知。

判断及指标数量取决于问题。没有证据支持投资结论时，当前状态写“还不能判断”；可以保留空判断列表，但必须在末节 coverageGaps 写明原因和影响。已有真实证据支持的问题或用户实际提出的假设可以保留，不冒用 `origin=user` 生成模型自己的假设。每个实质性判断的原始来源引用由结构化 evidenceIds 保存并渲染，不能仅在附件里留下来源。

## 📝 模型说明、审核与图表

有工作簿时按 [模型说明与理解验收](../../valuation-model-review/references/model-understanding.md) 复用同身份、版本及范围的原模型说明。四部分说明、输入角色、路径证据、复算与验收A保留为模型附件，正文第三节概括商业传导、第四/五节引用相关依据；附件不改变七节顺序。只要求模型说明时仍交付模型说明，不追加投资框架。

分别记录验收A与B的实际范围和状态。A检查输入→预测依赖→原输出；B检查证据→经营条件→投资判断→估值→改判条件。结构合法不等于语义或计算通过；缺工具时明确未执行，不声称完成独立审核。

业务驱动关系、KPI、情景估值、区间和催化剂先写入相应结构字段，阅读/导出可据同一数据生成图表。需要补充趋势、敏感性或追踪图片且工具可用时遵循 [图表公共规则](../../valuation-model-review/references/chart-quality.md)，分别放第三、五、六节或作为附件引用。没有足够数据时解释图表缺口，不伪造图形或以不存在的图片路径交付。

## 📝 提交与确认

1. 读取框架状态，基于完整现有内容更新，保留未受影响章节和稳定 ID。
2. 提交整份七节文档，使用实际文档版本和当前 expectedVersionId。工具校验失败时按错误定向修复，不能退回旧条目格式。
3. 成功后工作台直接把已保存草稿展示为“完整投资框架”，不依赖模型再次输出全文。`rendered_report` 是该文档的渲染结果；不要另行自由改写或在正文外增加未保存判断。
4. 回复简短说明已生成、待用户按钮确认即可；成功提交只是草稿，确认才发布。后续回复失败不撤销已经保存的草稿。确认后复用该文档，不再额外生成另一套正文。
