# 理解财务模型

交付的是“这位分析师怎么算的”，不是一张预测数字清单，也不是替他猜预测理由。取证遵循 [reader](../pe-financial-model-reader/SKILL.md)；已有读取结果可复用，不重复扫描全表。不要求整体估值报告工具。

## 从结果找到假设

- 锁定文件、指标、期间和单位。模型当时把哪些期间当实际，和今天是否已经公布，是两个问题。先用本地期间标签、公式关系、来源说明判断模型中的状态；不能用当前年份或文件名把旧预测改成实际。证据不够就保留未知。
- 从用户关心的输出向上追公式。跨表链接、加总、年化、增长率计算是中间步骤，不能因为到了另一张表就停止。读相关表头、标签、批注，直到到达有业务含义的独立输入，或明确的外链、动态引用、错误、循环或读取限制。
- 每个关键节点分别判断两件事：**实际 / 预测 / 混合 / 未确定**；**硬填 / 公式计算 / 外部引用 / 未确定**。历史值也可以由公式汇总，未来值也可以是硬填。只有结合预测期间和用途，才能把硬填数称为假设；公式内的常数也可能承载假设，不能只找无公式的格子。
- 判断计算方向，而非指标名字。例如收入由上期收入乘增长率生成时，增长率可能是输入；增长率由两期收入倒算时，它是结果，要继续追收入。链接到上一期假设的公式不是新的独立假设；去重并保留它影响哪些输出。
- 建模方式由原表决定。地区增长、门店数量与单店销售、面积与坪效、产品量价都只是可能的分解；成本也可能来自毛利率、成本占比或逐项费用。不要把这些例子强套到模型，更不能把分析师输入一个增长率解释成模型证明了定价权。
- 颜色只能辅助定位，不能决定实际/预测或输入/公式。以公式、期间和注释为证。相邻年份或地区可能换了算法；读代表性路径后检查所声称覆盖范围内的公式差异。不能把一条链推广成全公司，也不必遍历所有历史单元格。

## 停在哪里，要说清楚

工具的完整性只对本次请求成立。分页和 trace 的待续节点按 reader 指引继续；到达预算或不支持的引用时，列出影响结论的断点，不能写“已追到所有底层假设”。原文件有错误缓存不等于每项预测都错；只说明它是否落在当前链上。

输出位置偏僻、隐藏或无颜色都不是忽略依据。对目标价、价格基准等不同候选，检查用途、期间、依赖和来源。冲突未解决时分别保留，不擅选“最新”或把两套基准混算。局部重算可以校验一步算术，但不是整个模型重新计算。

## 呈现给人看的模型说明

先用白话给出已证实的建模方式，再用最短可复核计算链和关键输入支撑。围绕当前问题保留这些信息，不要求固定表格或固定数量：

默认先给简短结论和关键路径；只有用户要求追到底或详细审阅时才展开长链。不把工具日志或遍历到的所有单元格抄进回答。

- **结果与路径**：指标/期间/单位；结果坐标 → 中间计算 → 原始输入坐标；用业务语言解释运算。
- **输入的角色**：值、两项分类及证据、在哪些输出里使用。依赖相同输入的结果不能充当多条独立证据。
- **解释的限度**：模型怎么算（公式可证）；分析师为何选这个数（仅在批注/研报等有依据时归因）；假设是否可信（需要另外验证）。缺理由就提出具体问题，不写一个听起来合理的故事冒充原意。
- **尚未确认**：哪些部分未读、关键来源缺失或冲突、哪些结果仅是保存缓存。只列影响当前结论的事项，不堆技术告警。

关键输入指“在这条已核实路径上起作用”，不等于“最敏感”。没有可比扰动和完整计算，不给敏感性排名。不要自动改参数、更新历史值或输出买卖建议。

沿用 reader 返回的逐项引用；没有项目引用的附件用文件名与 sheet!cell。交给后续研究时保留同一组证据、期间、计算方向和未知项，不只传摘要。需要形成投资判断时再用 [投资研究](../pe-investment-research/SKILL.md)。
