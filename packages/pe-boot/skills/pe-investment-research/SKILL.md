# 从证据形成投资判断

聊天中要求完整投资研究及图文报告时，转交 [Investment Framework Builder](../investment-framework-builder/SKILL.md)，按阶段加载六个模块。本 skill 继续处理聚焦研究问题、项目框架草稿及仅有读取/提交工具的后台任务；后台不启动文件报告流程。

投资框架回答：为什么值得研究、判断依赖什么、拿什么验证、什么情况应改判断。资料与模型是证据来源，不是框架本身；没有模型也可以研究，不必为凑章节生成虚假结论。

有财务模型时先使用 [模型理解](../pe-financial-model-understanding/SKILL.md)。先把可证实的计算逻辑讲对，再研究假设是否站得住。既可独立交付模型说明，也可把它作为框架的一部分，不能把“预测了增长”直接升级成“公司有护城河”。

## 形成少数真正有用的问题

- 从已核实的模型输入、业务事实或互相冲突的证据出发，提出影响判断的问题，而不是复制指标清单。重要性可由计算路径、业务规模或已核验情景支持；没有量化支持就不宣称敏感性排名。
- 每个判断说明：当前主张；支持及反对证据；依赖的假设和计算路径；缺什么证据；什么可观察结果会加强或推翻它。明确哪些是模型事实、哪些是你的推断、哪些只是待验证问题。
- “为什么假设这个增长率/倍数”可能需要公司披露、行业数据、研报或直接询问分析师。可提出解释候选，但不能冒充分析师原意。不给没有证据的推断伪造引用；引用仅支持对应的前提。
- 市场共识、股价和实际业绩需要独立来源、发布时间、覆盖期间和口径。券商的一份模型不是市场共识；文件里的当前价不是今天股价。没有外部工具或未获本轮证据授权时，列缺口，不声称已联网核实。
- 新实际与旧预测必须同公司、期间、币种及调整口径比较。先指出原假设、最新观察和差异，再说明对判断的影响；不能只因时间过去就把预测改成事实。原文件不自动覆盖。
- 跟踪项写清指标、来源、可获得频率/事件、需重看的假设及更新动作。阈值来自模型、证据或用户设定；自己建议的阈值标为建议，不假装经过校准。不自动配置监控或交易。

## 不先替研究决定答案

Quality Compounder、Deep Value、Variant Perception 可以是后续比较的视角，不是必须提前选中的公司类型。投资周期由兑现路径、事件时间和不确定性推导；用户已给的期限或偏好是约束，没有则可暂未确定。分析项数量随问题决定，避免固定六章/十一章填空。

输出短而可追问：当前判断 → 关键依据/假设 → 最值得验证的问题 → 反证及跟踪。仅模型内的证据不足以完成投资结论时，仍交付已证实的模型说明和下一步问题。

## 使用现有框架工具

- 聊天里创建/修改项目框架：先读 `pe_investment_framework` 当前状态，保留条目 ID，以 propose 保存草稿；正式发布由用户确认按钮完成。
- 后台研究只使用本轮提供的 `pe_research_read` 和 `pe_research_submit`。工具 schema 是最终契约，不调用不可用的报告、外部检索或文件工具。
- `claim/rationale` 记录判断及模型路径；`evidenceIds` 只用真实返回的来源；`verification/invalidation` 写可观察条件；`coverageGaps` 记未证实理由、最新数据和依赖缺口。有证据前提的研究问题用 `origin=research`，说明证据支持的是问题的前提，不是已证明假设。完全无依据的 agent 猜想放 coverageGaps，不冒用 `origin=user`；该值只用于用户确实提出的假设。证据不足以满足提交契约时如实报告，不伪造条目。
- 更新说明哪条证据变了、为什么要改这项判断；没有实质变化就保留原判断。工具成功保存不等于判断正确，更不等于用户已确认。
