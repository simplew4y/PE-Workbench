# 估值模型解释

回答用户的问题，不逐格复述模型。解释“哪些假设通过什么计算影响盈利、现金流和估值”，区分模型事实和你的判断。

## 先有证据，再解释

需要读取原始 Excel 时，先使用 [财务模型阅读 skill](../pe-financial-model-reader/SKILL.md)。已有证据足够时不重复读取。截图、公式摘录或他人分析只能支持可见内容，不能声称核对过原工作簿。

问题涉及“预测怎么来的”或“真正的输入是什么”时，使用 [模型理解 skill](../pe-financial-model-understanding/SKILL.md) 追到独立输入，先讲清计算方向与假设角色，再评估估值含义。单纯解释建模逻辑不需要报告提交。

模型用了某种方法，不等于该方法合理；模型预测高增长，不等于高估值合理。多个方法和年度分别解释，除非公式或说明给出主次/权重，否则不擅自选一个主目标价。模型填写的股价不是实时行情。

影响答案的单位不明、缓存错误或依赖缺失要简短说明；不能为了报告好看隐藏它们。无关缺失不用逐项罗列，也不补空章节。未确认的股数尺度不得换算或参与每股估值。

## 📝 先模型说明，再继续分析

整体工作簿分析先执行已加载的 [模型说明与理解验收](../valuation-model-review/references/model-understanding.md)：交付结构概览及完整四部分模型说明，记录验收A的实际结果，再解释假设风险、做用户要求的审核或进入投资研究。不能只在内部略过这一阶段，或先给估值结论再补结构说明。

复用说明中的输入角色、公式路径、引用与缺口，不重新扫描同一版本。随后自动继续用户已请求的模块；仅要求模型分析时，不额外启动完整投资框架或市场预测。单项问题和截图解读沿用原有范围。

## 📝 按问题组织回答

- 只问一个数或公式：给结果、口径、来源，以及必要的计算关系，不扩展成整份报告。
- 问整体逻辑：围绕模型逻辑框架、核心驱动因素、盈利预测与敏感性分析、模型核心风险点展开。它们是可选组织方式，不是填空题；篇幅按模型和问题决定。
- 问为何变化：沿真实公式分清经营假设、盈利预测与估值参数的贡献，不把指标并列解释成因果。
- 问敏感性：区分原表结果和补充假设测算。后者须有完整输入、适用公式、统一口径和固定条件，标记“假设情景，非原表结果”。输入不足就说明不能量化的原因，不编造精确变化或敏感性排名。

用户问“哪些假设最重要、最影响估值”时，先从已确认的估值输出调用 `pe_driver_discover`。它只给出结构上连接的候选假设，不能把 discovery rank 写成敏感性排名。存在可用重算引擎时，再调用 `pe_driver_sensitivity`：只扰动上游可编辑输入，在隔离副本中重算公式型中间指标和最终输出，并按实际估值变化排序。公式格不能被覆盖后冒充模型原生情景；未成功重算的候选保持“未测试”。

完成前置模型说明后，估值解释阶段可先概括结果及最短计算链，再解释少数关键驱动和假设失效后的影响。例如 P/E 模型中的 EPS × 倍数，或 DCF 中的现金流折现、净债务调整、股数及每股结果；只用原表实际采用的关系，不用这段结果概括替代完整模型说明。

需要深入解释不同估值方法、经营传导或补充敏感性测算时，读取 [详细分析参考](references/detailed-analysis.md)，只用与问题相关的部分。不要自动扩展成全面审计、模型修改或投资建议。

## 交付

默认中文。集中比较数字时用紧凑表格，正文解释含义，不重复所有数字。

面向投研人员的主报告只保留结论、3—5 个核心驱动、关键预测和会改变结论的风险。工具调用、U1—U6执行记录、逐格公式链、错误格清单和完整审计结果不进入主文；需要留痕时保存为生成附件。不要把“完整”理解成穷举所有检查步骤。

重要数字和判断附引用：工具直接返回 `markdown_citation` 时原样使用；Excel 读取工具返回的是 `evidence_id`，按 `[<文件名> <sheet>!<cell>](#pe-source?evidence_id=<evidence_id>)` 组成，ID 原样复制。保留 `#pe-source?evidence_id=`；不要展示裸 source ID 或编造链接。chat 附件用文件名和具体坐标。引用必须支持该项结论，推断明确标出。

项目中用户要求整体估值模型报告、且有 `pe_valuation_report` 时，读取 [报告提交说明](references/report-delivery.md)，通过工具校验后交付。单项问答、chat 附件和投资框架生成不套用该报告流程；框架任务用自己的结构化提交工具。

只在用户要求保存时创建 Memo 或 Research Note，不修改原工作簿。
