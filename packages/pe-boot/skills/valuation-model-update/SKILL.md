# 估值模型滚动更新

目标是延续原研究模型，不是模仿内部研究员重建预测。先按依赖的 `valuation-model-review` 完成同版本、相关范围的模型说明与验收A，再修改副本；原始工作簿始终只读。

## 更新边界

按以下顺序处理，不能跳过前一层直接生成新假设：

1. 已披露实际值：核对期间、单位、币种和业务口径后写入对应历史期。
2. 机械计算：保留原公式、跨期链接和实际预测边界，使用可用计算引擎重算。
3. 原模型假设：没有实质冲突时沿用，不因单期噪声重写整条预测。
4. 假设修订：只有实际、指引、历史范围或行业环境与原假设发生实质冲突时，才提出局部修订或情景。

外部环境是复核信号，不是覆盖公司预测的公式。公司与行业方向相反时，先查新品、份额、渠道、区域结构和低基数等公司特异性证据；没有证据再要求修订。经营变化先修改经营驱动并沿原公式传导，不能直接用市场走弱替代估值倍数判断。

## 误差与“不够合理”的处理

比较并永久保留原模型预测、财报前一致预期和实际结果。调用 `pe_assumption_review` 时：

- 正负方向相反必须复核，但不能自动替换原值。
- 幅度使用指标自己的历史波动、披露指引或业务容差；没有容差时不得用统一百分比宣称误差过大。
- 连续偏差、超出历史范围或达到估值重要性门槛时，提出局部修订；重大影响同时提供基准、悲观、乐观情景。
- 公司背离行业但有可定位的公司特异性证据时可以保留原假设；记录证据和持续性问题。
- 证据冲突、缺少修订依据或无法解释异常时，保留旧假设并建立未解决问题，不填伪精确数字。

大误差不等于把预测改成实际值。先拆销量、价格、结构、汇率、利润率和一次性因素，判断偏差能否延续，再修改直接受影响的输入。

## 产物与版本

所有工作簿改动通过 `pe_model_update operation=apply` 另存到项目 `generated/model-updates/`。每个变更必须提供单元格、原值、新值、类型、理由和证据；工具拒绝覆盖公式单元格或原值不匹配的请求，并从当前已晋升基线继续滚动。不得覆盖上传原件。每次交付：

- 更新后的Excel；重算失败时版本为 `unavailable`，不得把旧缓存称为新结果。
- 原预测、一致预期、实际及偏差桥。
- 原值、新值、修改类型、模型位置、证据、判断理由、置信度和待确认项。
- 收入、利润和估值变化归因；只归因实际复算覆盖的路径。
- 计算、口径、合理性和估值敏感性校验结果。

版本状态遵循 `pe_assumption_review`：

- `current_research`：只补事实、滚动公式或记录非重大偏差，硬性校验通过。
- `candidate`：存在未复核假设、重大情景缺失、证据冲突或未解决异常；可以展示，不得成为下一轮基线。
- `reviewed`：关键修订已由研究员确认且硬性校验通过，可以成为基线。
- `unavailable`：公式、口径或关键计算校验失败；保留记录，但估值不得下游使用。

`current_research` 和 `reviewed` 可通过 `pe_model_update operation=promote` 成为下一轮基线。`candidate` 只有在 `approval_eligible=true` 时才允许研究员用 `operation=review` 批准；证据冲突、缺少情景或硬校验失败不能靠批准绕过。拒绝决定和历史版本保持不可变。读取历史使用 `operation=list`。

投资框架可以独立更新。模型不可用不阻止有效证据和论据变化保存。

## 完成条件

只有在以下内容齐备时才称本轮更新完成：原件身份和比较基线已冻结；实际值与口径有证据；每个改变能回到原输入和下游路径；原预测未被覆盖；新Excel或change set可复核；估值变化可解释；版本状态与校验结果一致。下一轮财报再比较原预测、更新后预测、一致预期和实际，用于回测规则，不为本轮结果事后合理化。
