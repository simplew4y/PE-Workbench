# Issue #1 合成模型验收

范围：公共规则的输入角色、两类敏感性、成果交接及任务边界。完全使用合成数据，不需要真实投研文件或模型凭据。

运行 `python3 packages/pe-boot/evals/shared-model-rules/fixture.py` 在临时目录生成并通过项目reader核对两版工作簿，检查公式、保存值、版本差异及读取前后哈希。指定 `--output /tmp/pe-issue-1-fixtures` 可保留工作簿；脚本拒绝覆盖已有文件。该脚本只生成已知公式及缓存，不是Excel计算引擎，也不评价agent。

v1、v2均为Model表两年预测，区别是B2增长输入从10%改成12%；C2沿用B2、C3沿用前期收入。毛利率和增长率展示行由收入/成本倒算。所有参数是合成条件，不代表任何公司。

## 行为执行

`cases.json` 每项记录入口、逐轮用户请求和判定标准。被测agent只接收工作簿、skill入口及turns，不给must/fatal、fixture脚本或计算答案；对话接续用上一轮实际成果，不预造A通过。完整研究用临时项目，受限后台用真实读取/提交适配及临时入库数据，不通过额外工具放宽权限。

分别保存每题实际回答、工具轨迹（含读取范围及版本）、生成物和逐条核验。同版本复用允许Reviewer定向抽查，不按“零读取”判定通过。出现任一fatal则失败；缺少执行证据标未验证。文件/图表需检查实物，不能用关键词、加载测试或章节齐全代替行为验收。

默认只执行不调用模型的来源检查及自动回归。真实模型行为运行需有可用且获授权的执行环境；未执行时保留“未运行”，不得将faux响应视为模型质量证明。
