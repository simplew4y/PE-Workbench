# 财务模型理解：要交付什么

## 会议要求

周灵反复强调的是：让研究员快速知道“这位分析师的预测是怎样做出来的”。不是取出收入、利润、目标价，也不是先给公司定一个投资类型。

例如：

预测收入 → 地区收入加总 → 上年同期收入 × 预测增长与汇率影响 → 分析师输入的增长/汇率假设。

这是一个可能的模型，不是标准答案。另一位分析师可能用门店数 × 单店销售，甚至面积 × 坪效。只有读实际公式才能分清。成本、费用、现金流、估值同理。

会议给出的优先级是：

1. 先准确还原模型里已有的计算、事实与假设。
2. 再结合其他证据讨论为什么采用这些假设、是否合理。
3. 再加入市场预期、判断的不确定性、反证和更新。

公式能证明“如何计算”，通常不能证明“分析师为什么相信增长会达到这个数”。这两层必须分别交付。

## 和投资框架的关系

模型理解可以独立使用，例如接手一个券商模型，或比较两位分析师的建模差异。它也是投资框架的重要输入，但不是整个框架。

模型说明：这个结果依赖哪些输入、怎么算、哪里还没核实。

投资框架：这些假设里哪些决定我们的判断，有什么依据，接下来验证什么，什么变化会让我们改判断。

不规定必须做六种或十一种分析。通常从收入、成本/利润、现金流、估值中挑与当前问题相关的路径，再按真正有影响的假设展开。没有证据的部分保留为研究问题。公司类型、投资周期可以是研究后的判断，用户已明确的偏好则是约束。

## 为什么难

- 同一个指标名可以是输入，也可以是结果。增长率可能驱动收入，也可能由收入倒算。
- “过去/未来”与“硬填/公式”是两个维度。历史值可以是公式，预测值可以是硬填；颜色没有统一规则。
- 模型跨表、跨期间，存在链接假设、公式内常数、不同预测期切换算法。只追一层或只查黄色格子会漏。
- 外链、动态引用、缓存错误和冲突价格会使证据不完整。工具读到了数，不等于理解了口径或证明结果正确。
- 模型中没有写的理由不能靠语言流畅补出来。需要外部来源或和分析师确认。

## 实现

| 能力 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| pe-financial-model-reader | 结构导航、定向读值/公式/批注/格式、追踪及坐标引用 | 投资判断、报告模板 |
| pe-financial-model-understanding | 从输出追到独立输入，判断计算方向、期间和角色，写清模型逻辑 | 编造分析师动机、证明预测会兑现 |
| pe-valuation-model-explainer | 根据已核实路径回答估值含义、风险和特定情景问题 | 重新发明另一套读取流程 |
| pe-investment-research | 把模型假设与其他证据变成判断、验证问题、反证和跟踪项 | 预先套公司类型、自动发布框架或交易 |

这就是第一本小型 skill book。按任务扩展，不按每家公司复制一套。只有遇到确有不同分析方法且现有规则不足的任务，再增加专题指引。Hermès 的数字和坐标留在测试集中，不放进生产 skill。

聊天通过 pe_load_capability 按需加载；模型解释依赖理解，理解依赖 reader。投资框架同时加载理解和投资研究，不加载整体估值报告。

后台框架 agent 只有 pe_research_read / pe_research_submit，启动时从同一能力注册表加载三个 skill 正文。没有文件或外部检索权限，因此必须列外部证据缺口，不能假装自己补过行情。项目、附件、后台仍用同一 workbook_reader.py。

预处理仅提供结构导航与文字索引，保留批注和格式。问题驱动的公式链及语义判断在任务中形成；不把整本表塞入上下文，也不把一次分析永久当真。当前不新增语义缓存或自动覆盖模型。

## 交付及验收

用户看到的应是简短的模型说明，而非必须阅读 JSON：

- 建模方式与最短可复核链。
- 关键输入、期间/单位、实际或预测、硬填或公式，以及引用。
- 哪些理由原表有依据，哪些只是推断或待问问题。
- 影响答案的未追踪依赖和冲突。

最重要的 rubric 是**有没有找对独立输入与计算方向，而且每个重要说法都能回到证据**。公式方向弄反、把预测当事实、编造分析师理由、隐藏会改变结论的冲突，任何一项都不能靠文笔补分。

测试分三层：工具读取回归、运行时真正加载 skill 的接线测试、不给答案的 agent 实测。五道 Hermès 题及验收条件见 ../evals/financial-model-understanding。单表通过不代表跨行业泛化；下一步需要不同建模风格和外链不完整的样本。
