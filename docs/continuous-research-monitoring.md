# 持续跟踪与投资框架自动调整

## 当前实现

项目右侧「投资框架」是统一入口。首页展示最新结论、两条变化摘录和待核实事项；「查看变化」「查看依据」按需展开。「自动跟踪设置」位于同一面板内，技术日志收在设置里的「历史检查与运行详情」；完整框架和历史版本另外展开阅读。摘录直接来自本轮变更文本，不额外生成投资判断。

设置保存在项目 SQLite 中，Web 启动独立后台 Worker；Worker 使用 Pi SDK 的研究执行器。关闭页面不停止跟踪，暂停按钮会停止后续采集并中止当前分析；已经发布的版本保留。

```text
到达检查时间
  → 按项目配置查询 Wind：新闻 / 公告 / 财报 / 事件 / 股东 / 行情
  → 保存版本化原始响应；逐项记录失败，继续其他类别
  → 检查项目里已完成入库的 PDF、Excel、Wind 快照和已保存 Memo
  → 固定本轮输入版本、观察时间、当前框架版本
  → 与上次处理的输入比较
       没有变化 → 保存检查记录，不调用模型
       有变化   → Pi SDK 独立研究会话 → 阅读证据 → 提交结构化框架
  → 校验引用、资料准备状态、框架基准版本
       内容不变 → 不产生新框架版本
       人工模式 → 保留待确认草稿
       自动模式 → 发布新版本，保留旧版本
  → 保存执行记录、条目差异和 Markdown 报告
```

Pi SDK 负责模型推理和受限证据读取，不负责计时。Worker 负责真实时钟、项目调度、持久记录和调用预算。后台会话不复用正在聊天的会话，不加载编码工具或项目内的技能指令。

## 操作

1. 先保存一份正式投资框架。
2. 打开「投资框架 → 自动跟踪设置」，在「关注内容与资料来源」确认公司身份和每类查询。留空表示不调用这一类。
3. 设置 1–168 小时检查间隔，选择「自动更新框架」或「生成草稿，由我确认」。默认 24 小时、自动模式、纳入 Memo。
4. 点击「启用跟踪」立即开始首轮。之后可以修改设置、暂停，或点击「立即检查 / 恢复 Worker」。
5. 展开运行记录看来源查询、输入清单、分析状态和条目变更。点击原始响应引用查看快照，下载本轮 Markdown。
6. 人工模式下可确认或拒绝草稿。框架已经被他人更新时，过期草稿不能直接发布，需要重新复盘。

普通对话尚未保存的临时观点不进入后台。需要长期跟踪的观点先通过已有 Memo 功能保存。Memo 是观点背景，不能替代原始事实证据。

## 展示设计及原因

| 展示层 | 内容 | 要解决的问题 |
| --- | --- | --- |
| 运行状态 | 启用/暂停、Worker 心跳、下次检查时间 | 区分“保存了计划”和“后台确实在工作” |
| 来源记录 | 类别、查询、时间、响应快照、错误 | 避免把 API 成功等同于取得有效证据 |
| 输入清单 | 本轮文档版本、Memo 版本、框架基准、观察时间 | 说明本轮究竟依据了什么，支持复查 |
| 分析进度 | 读取证据的工具请求、提交与校验阶段 | 展示可验证的执行过程 |
| 框架差异 | 原判断、新判断、变更理由；旧版本仍可浏览 | 解释“为什么改”，支持人工干预 |
| 运行报告 | 每轮生成独立 Markdown | 便于下载、审阅和留档 |

展示的是工具执行事实与模型给出的结论依据，不把模型隐含推理当成证据。单个来源失败会单独出现；其他成功资料仍可用于分析。检索结果保存成功，仅表示取得了响应，主体相关性、期间、单位和实际/预测仍需复盘核对。

## 运行与边界

- 页面启用时启动现有 `services/pe-research/worker.mjs --cwd PROJECT --dataset ID --monitor`，后台每 5 秒检查到期状态。也可使用原有 `--registry PATH --dataset ID` 方式定位项目。未传 `--monitor` 仍处理原有研究任务队列。
- 模型默认沿用 Pi SettingsManager 保存的模型，也可用 `PE_RESEARCH_PROVIDER`、`PE_RESEARCH_MODEL` 指定。Wind 使用现有服务端凭证；计划、报告和界面不保存 API key。
- 一个项目一个 Worker 文件锁；数据库中每项目仅一个活跃跟踪运行。单轮总预算 9 分钟、自动跟踪的研究预算 5 分钟，研究执行器最多 12 轮。原有手动研究队列仍为 120 秒预算。暂停或配置变更会中止旧轮，发布事务再次核对计划版本与运行租约。
- 进程中断后，运行租约到期可恢复；发布后突然退出会根据发布请求回执识别已提交版本。失败不会推进已处理输入清单。运行记录保存在数据库，报告放在 `generated/monitoring/<runId>.md`，启动日志为同目录 `worker.log`。
- 数据相同的 Wind 响应复用既有快照。当前去重依据完整响应和资料版本，不保证将不同媒体的同一事件合并成一条；重复报道不能当成多条独立证据。
- 新资料检测针对**已上传且解析完成**的资料，不会扫描电脑任意目录，也不代替 PDF/Excel 上传与解析。
- 单轮最多 100 个文档版本；Memo 背景超过 60000 字符时明确报错，不静默截断。
- 本机休眠、关机期间不能运行。恢复后补一次到期检查，不逐个回放错过的小时。首版没有安装开机服务或系统级进程监管；后台异常退出可点击恢复，长期无人值守部署需要由部署环境监管同一个 Worker。
- Wind 是检索通道，当前 news/announcements 每次最多 5 条，不能保证全量披露覆盖；源端为空、报错、证券映射不明需要保留缺口。框架自动发布有结构、引用和版本校验，但事实相关性的判断仍依赖研究 Agent。

## 验证

核心回归覆盖自动发布、原文输入不变时跳过、新资料触发、人工草稿、来源失败、同项目并发、暂停、人工抢先发布、设置版本冲突和跨项目访问。框架与 Pi 执行器既有测试、Web 框架 API 与研究组件测试同时运行。真实项目的来源可用性与模型结果以其运行记录为准，不把测试替身结果作为真实投资结论。
