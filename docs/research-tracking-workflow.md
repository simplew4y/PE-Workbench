# 统一研究追踪流程

日常入口：聊天工作区的“投资框架”侧栏。完整记录入口：`http://127.0.0.1:30141/research-workbench`。

## 侧栏自动更新

只保留“立即更新”和“开启／关闭自动更新”两个更新按钮。首次点击无需选择模型、绑定输入或确认日期：后台读取当前完整框架及项目已有文件，自动确认公司与代码、当前模型版本、估值日期、可写输入和敏感变量。日期必须来自模型原文或框架已明确的估值基准日，不能以文件名替代。

每轮重新检查项目文件，包括新上传资料，再按估值日期至运行当天逐季查询 Wind。Wind 只接收主体、指标、期间和口径。可比证据用于修改框架及模型输入；信息不足时保留原值并说明原因。框架保持原有七节格式，模型保留公式，重算与校验成功后自动设为当前版本，保留旧文件和简短修改说明。

手动更新不自动开启定时计划；开启后每 168 小时检查。本机休眠或服务关闭期间不执行。过期且离线的手动运行会在状态轮询时结束，可重新点击“立即更新”。

## 工作台手动审阅流程

以下是工作台保留的逐项审阅与显式模型验收流程；侧栏自动更新不要求填写这些配置。

1. 选择研究项目。在聊天工作区生成并确认完整七节框架，作为首个正式版本。
2. 在“模型与追踪”绑定已入库 XLSX 的可写输入。确认指标、主体、期间、单位、范围、币种、工作表、单元格及原值。可从本轮观察预填口径，但配置只用于后续新轮次。
3. 上传新增资料，或选择 Wind 财务数据，开始本轮更新。系统固定输入版本，执行提取、影响判断、局部修订和校验。
4. 在“本轮更新”审阅变化，点开证据核对原文。同一语义组及相依正文必须一致采用或拒绝；独立的修改组仍可部分采用。结构约束不等于研究结论已通过语义审核。
5. 确认后发布框架。Excel 单独验收：下载实际写回、公式保留且重算校验通过的副本，再显式设为下一轮模型基线。推进基线同时更新映射中的原值，并保存包含操作者、时间、前后版本和配置修订的不可变采用回执；后续采用其他版本不会抹去旧版本的采用历史。
6. 从“版本历史”查看每轮结果、异常、采用理由及下载报告。历史支持继续加载，不仅展示最近八轮或最近一百轮。

旧测试入口 `/framework-iteration-test` 保留。纯演示移动到 `/research-workbench/demo`，不会伪装成真实项目结果。

## 追踪触发与账户

- 新追踪设置采用 `pipeline: iteration`，手动运行、定时检查和官方文件入库共用结构化迭代、审阅和历史。
- 定时检查优先处理新增且已完成入库的文档；启用 Wind 选项后，无新文档时再查询财务信息。
- 后台使用显式服务端 `PE_INGEST_LLM_BASE_URL`、`PE_INGEST_LLM_API_KEY`、`PE_INGEST_LLM_MODEL` 和可选 `PE_INGEST_LLM_EXTRA_BODY`。不借用本地聊天凭据或其他账户。启用前须确认费用，页面不返回凭据。
- 手动平台迭代使用当前登录账户。模型不可用时仍可查看历史、取消和审阅，不要求为这些本地操作购买模型调用授权。
- 后台供应商费用没有目录估算，记录中的零估算不是免费。平台手动运行的费用仍以平台账单为准。
- 后台轮次失败后恢复仍使用原服务端模型；不会悄悄改用聊天账户。
- 调整运行间隔、暂停和重新启用保留已消费资料，不自动重复处理已经无变化或拒绝的资料。暂停不要求供应商凭据；暂停期间保存间隔和信息源修改仍然生效。
- 工作台流程默认人工审阅，不因为旧计划为 `auto` 就绕过审核。侧栏明确采用直接更新策略，由后台核验后自动发布。旧计划和原股票行情追踪能力保留。
- 官方文件投递必须持有 `PE_WORKBENCH_INGEST_TOKEN`；此服务凭据只授权精确的 `POST /api/pe/information-candidates`，不授权文件、聊天或其他接口，也不绕过主机、来源或额外密码检查。

## 模型安全边界

- 只有精确匹配并核实证据的实际数值自动写入副本。口径不明、期间不符、多重匹配、单位/币种不清及缺少关联影响的观察保留为未写回项。
- 预测或假设只形成待研究员处理的建议，不直接把券商预测变成自身假设。现有聊天模型更新工具仍可进行假设审阅、情景检查和受控写回。
- 不覆盖公式，不修改上传原件。工作台由用户验收后推进基线；侧栏在重算与校验成功后自动推进。当前仅支持 `.xlsx` 写回。
- 真实重算需要 Python Excel 环境与 LibreOffice，可通过 `PE_SPREADSHEET_RECALCULATOR` 指定可执行文件。
- 模型重算失败显示“不可用”，框架结果仍保留；不能把框架发布当成模型交付成功。
- 配置与输入过期时拒绝写回。中断的不确定写入不自动重复；修复环境后建立新轮次，旧运行及文件保留。
- 每次模型交付按运行标识幂等，显式推进基线使用配置版本校验，防止并发覆盖。
- 模型原件无法读取时单独显示错误，仍可重新绑定文件或暂停追踪，不会让整个配置页不可用。

## 故障处理

| 页面状态 | 操作 |
| --- | --- |
| 没有框架基线 | 返回工作区确认完整框架 |
| 待审阅 | 核查证据与关联修改，再发布或拒绝 |
| 失败／待处理 | 查看原因，修复凭据或环境后恢复；基线已变化时取消并新建 |
| 模型不可用 | 保留原基线，检查重算环境、原值及映射；不要采用失败副本 |
| 后台未就绪 | 检查服务端配置，点击“立即检查／重启后台” |

存在未处理轮次时，定时调度不会反复新建并重复调用。关闭计划会停止后续检查，进行中的任务在检查点停止。本机休眠或进程退出时不执行任务；没有安装系统守护进程或防休眠服务。

## 本次验证边界

定向回归覆盖归档路径与符号链接、审阅一致性、调度幂等与恢复、模型映射与版本推进、接口授权、历史分页、轮询竞争和重试请求身份。外部模型与 Wind 使用替身或本机模拟端点，不产生真实供应商调用。

本轮自动识别相关定向验证共 101 项通过；Web TypeScript、ESLint 和 SDK 编译通过。已使用本机 LibreOffice 执行模型文件实际写回、重算与基线推进的 2 项测试并通过。本轮未调用真实 Wind／LLM 更新用户项目；浏览器工具不可用，视觉点击验收未完成。

本机现有“阳光电源2”项目的 `research_schema_version` 为 `3`，当前 main 的研究存储仅支持 `1/2`，会拒绝读取并导致项目接口失败。没有降级版本号、删除或重建数据库；需确认 v3 的结构约定并完成无损兼容验证后，才能把该现有项目列为验收通过。

Web TypeScript、ESLint 和工作区依赖检查通过。全量 `npm run check` 首次在既有 `packages/ai/test` 的 Kimi／DeepSeek 模型标识与本机模型目录不一致处失败；再次执行时，非本轮未跟踪的 `output/biome.json` 因非法 UTF-8 及嵌套根配置使 Biome 提前退出。没有修改这些文件、删除测试或降低检查。
