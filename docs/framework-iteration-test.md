# 新增资料驱动投资框架迭代

入口：`http://127.0.0.1:30141/framework-iteration-test`。

## 使用

1. 登录平台账户，在模型设置中选择平台模型。
2. 在原聊天页面基于指定资料生成完整七节框架，点击“确定投资框架”。
3. 打开测试页面并选择该项目。需要自动发布时，显式勾选“登记此项目为测试项目”；服务端保存标记。
4. 上传 PDF、XLSX 或 XLSM，点击“上传并运行完整流程”。
5. 查看解析警告、实际读取位置、提取信息、影响分析、完整候选框架、变化原因和原文链接。
6. 普通项目点击“接受并发布”或“拒绝草稿”。没有实质影响的运行不生成新版本。
7. URL 保留项目和运行 ID，刷新可恢复显示。“下载运行报告”包含基线、阶段产物、候选、发布回执及可获取的调用指标。

不修改原始 Excel，不重算模型，不更新股票预测或模拟交易，不查询 Wind，也不接入现有上传按钮或定时跟踪。

## 执行与恢复

Web 服务使用后台任务执行。关闭浏览器不取消任务。每个项目最多一个排队或执行中的任务；重复请求 ID 和相同输入返回原运行。

SQLite 增量建表保存运行、执行尝试、阶段尝试、不可变有效产物和模型调用统计。租约 60 秒，每 10 秒续期；三个模型阶段分别最多 5 分钟（包含重试），一次执行最多 20 分钟。瞬时网络错误最多重试两次，认证、余额和输入错误不自动重试。

完整框架引用在修订提交时校验。恢复时重验已保存修订产物；若发现无效引用，原产物与失效原因保留，仅重新生成修订，不覆盖原记录或重复完成的提取/影响阶段。

Web 重启后，过期执行进入待处理。重新登录后点击恢复，从最后一个有效阶段重新执行；不恢复模型会话中间状态。取消的运行不能恢复。资料或基线变化会阻塞旧运行，应基于最新框架另建运行；旧产物保留。

每个模型阶段重新检查授权，并固定创建运行时的平台模型 ID。自定义模型、失效登录、余额不足或模型不可用均不会触发供应商回退。密码不进入代码或报告；令牌沿用账户机制。

发布事务校验租约、取消状态、项目测试标记和预期基线，并同时写入版本与运行回执。普通项目的接受和拒绝也校验当前草稿状态。

```bash
cd ../../apps/web
node --test lib/pe-ingest/worker.test.mjs
node --test app/api/pe/framework-iterations/route.test.mjs
```

启动开发服务使用 `npm run dev`。Web 将 SDK 作为外部模块加载；修改 `packages/pe-boot` 后，在仓库根运行 `node_modules/.bin/tsgo -p packages/pe-boot/tsconfig.build.json` 并重启开发服务，不能仅依赖页面热刷新。修改解析 worker 后运行 `node apps/web/scripts/build-pe-ingest-worker.mjs`。不要在当前开发目录运行生产 Web 构建。

## 输入与研究限制

沿用研究输入上限：最多 100 个文档版本。新增文件总计不超过 300 MiB，单文件不超过 100 MiB。PDF 沿用已有解析页数限制；扫描件或不可读内容通过警告和缺口展示。不会自动纳入聊天、研究卡片或其他外部资料。

提取以约 12 条核心观察为目标；这是提示中的分析范围限制，未覆盖部分需明确保留。数值保留原文单位，PDF 引述逐段核对解析原文，所有引用必须能定位至固定资料。修订 Agent 仅提交允许修改的完整章节，服务端保留其他章节、标题和结构版本，组合成七节候选。校验会拦截把相同 RMB million/billion 数值直接复制到错误人民币量纲的情况，但不能验证全部换算、期间、销量口径或因果归因，仍需人工核查。平台费用为目录估算，实际结算以平台账单为准。

真实业务验收结果见 [验收报告](./framework-iteration-acceptance.md) 与 [完整运行记录](./framework-iteration-runs)。三类真实调用已完成，流程通过，但研究口径、事件含义和部分提取字段仍未全部通过人工核查。测试替身仅验证流程和权限边界，不计入真实 LLM 效果验收。

## 📝 2026-10-01 研究校验修复

处理器升级为 v2。每条观察必须提供单期/累计/时点分类、截至日期、业务口径、原文上下文、事件分类和待核查原因。PDF 的主引述和上下文引述都必须匹配冻结证据；累计期间必须含原文截至日期。季度标签矛盾、明确预测误标事实、已披露门店误标指引以及销量改写出货会被拦截。影响分析须明确比较对象的期间和口径；不一致时不能标为可比。

金额检查覆盖提取缺口、影响建议以及关联证据的候选内容，避免无关章节出现相同数字导致误报。仍主要拦截相同原始数值复制到错误倍率的情况，不保证任意换算或自然语言判断正确。

修改判断的建议必须包含判断章节；指定章节及判断没有改变时，修订提交失败。研究设置可同步资料范围，但研究期限和用户偏好不能改变。新候选的统一信息截止日置空，避免将旧日期或上传日期当作披露日期；实际资料清单、版本及纳入时间显示在运行页面并随报告保存。

存在待核查原因、事件语义疑点、未知口径或表格资料时，即使登记为测试项目也转为人工确认。发布完成不代表研究质量通过。v1 运行保留记录，但不能恢复或接受旧草稿；应取消旧任务后基于当前框架新建运行。同版本恢复会重新校验提取和影响；无效修订及其下游校验产物保留失效记录，重新修订，不复用旧发布草稿。

本次修复使用离线回归和代码检查验证，没有重新调用付费模型，也没有改写历史实测结果。完整运行 JSON 目录仍为本地资料，不随 Git 提交。
